# Feature 4: Imaginary Numbers

There are times when the output of a closed form may include imaginary numbers, so the question is this: how could this tool use this information even though standard SMT solvers do not support complex numbers?

The idea is that if the closed form is complex, it can be written so that it uses two variables that store the real and imaginary components, and then the transition step in the consecution can be written using complex multiplication. Then, when the bounds are being created, the bounds will be made for the magnitude of the system itself. There is already a way to write a complex conjugate pair in a closed form as a system that includes sine and cosine, and so I will always translate complex roots into this setup so that there will be a root that represents the magnitude, and one that represents the phase. Further, if the phase is rational periodic, then that means I could create a set of lemmas that state using modulo arithmetic each possible value that the period could be at depending upon where it is in the period itself. But, if the root is not rationally periodic, then that means that we can just calculate the value at each time step, and slowly calculate it.

In order to do this, the python script must do this separation of the magnitude root and the phase root. I can't currently find the formula, but from what I remember it is a common practice to have it be something like (r)^n(Asin(n\theta)+Bcos(n\theta)), or something like that. Thus, we would need to rewrite how the tool inputs the closed forms, since there would be a real and imaginary component for it. This would also mean we would have to change how the data structure stores information, or at least something along those lines.
